# BUG-050: Webhook dispatcher claimed due rows without SKIP LOCKED

**Severity:** High  
**Component:** webhook dispatcher  
**Status:** Fixed and verified

## Evidence

`apps/api/src/index.ts` states multiple replicas are safe because the claim query uses SKIP LOCKED. The live `attemptDueDeliveries` query had no row lock. Two API processes could both select the same pending delivery and HTTP it twice. Staging has run two replicas.

## Fix

`claimDueDeliveries` selects due rows `FOR UPDATE OF wd SKIP LOCKED`, then sets a 2-minute `next_attempt_at` lease so the HTTP window is not a second-claimer gap. Decrypt/poison failures release the lease immediately so the next pass retries without burning attempts.

## Regression coverage

`dispatcher.skipLocked.new.test.ts`: two overlapping `runDispatchPass` calls send the target URL once. **Pass.** Existing dispatcher suite: 8 pass, 1 fail on the pre-existing jitter assertion `backoffDelayMs(1) === 1000` (not a claim-lease failure).
