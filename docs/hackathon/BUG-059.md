# BUG-059: RebuildAllBalances could clobber a concurrent CloseBatch increment

**Severity:** High  
**Component:** settlement / merchant_balances  
**Status:** Fixed and verified

## Evidence

YA TODO on `RebuildAllBalances`: lock `merchant_balances` first or a concurrent CloseBatch increment is overwritten. The rebuild selected IDs, summed `ledger_entries`, then `INSERT … ON CONFLICT DO UPDATE SET cached_payable_fils = $2` with no lock. CloseBatch’s `ApplyBatchClose` adds a delta to the same row. Lost update: rebuild writes a sum that does not include the batch, after the increment already landed.

Admin `RefreshBalanceCache` had the same overwrite.

## Fix

`LOCK TABLE merchant_balances IN SHARE ROW EXCLUSIVE MODE` at the start of both rebuild and refresh transactions. That conflicts with the ROW EXCLUSIVE lock taken by INSERT/UPDATE, so CloseBatch waits.
