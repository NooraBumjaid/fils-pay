# BUG-045: Settlement repriced captures after a platform tier change

**Severity:** Critical  
**Component:** payments / settlement  
**Status:** Fixed and verified

## Evidence

Capture records the exact `feeFils` charged in `transaction_events.metadata`.
`CloseBatch` previously recomputed fees using the platform volume tier at
batch-close time. Since each merchant close advances the shared lifetime
counter, a capture made below the tier threshold could be settled at the
discounted tier after another batch crossed that threshold. The batch fee
would then disagree with the immutable capture fee ledger legs.

## Fix

Settlement now reads and sums the fee recorded on each capture event. For
legacy events without `feeFils` metadata, it retains the prior per-event
recomputation fallback. Explicit MDR recalculation remains the separate,
intentional path for repricing historical batches.

## Regression coverage

`TestCloseBatch_UsesCaptureTimeFeeAcrossVolumeTierChange` records a capture
below the platform tier threshold, moves the counter to the threshold before
batch close, and checks that the settlement batch fee still equals the
capture-time fee and fee ledger entries.

The full database-backed `apps/settlement/internal/settlement` test package
passed against the isolated `fp300audit` Postgres instance.
