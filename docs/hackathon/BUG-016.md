# BUG-016 — Refund reporting columns and event rollups were missing

**Severity:** High — refund activity absent from settlement and daily reports  
**Area:** FP-300, reporting

## Finding

The reporting rollup attempted to write refund counts and gross amounts without a migration adding those columns. The consumer also did not select refund success events, and daily grouping used UTC rather than the Bahrain business date.

## Fix

Migration 0073 adds refund reporting fields. The consumer now processes `refund.succeeded`, rolls refund count/gross into daily summaries, groups by Bahrain date, and preserves refund adjustments in payout trends and rebuild queries.

## Verification

Added a regression test around the UTC/Bahrain date boundary. Typecheck passes; reporting database tests require PostgreSQL, which is unavailable here.
