# BUG-049: Redelivered acquirer callbacks inserted duplicate notes

**Severity:** High  
**Component:** acquirer callbacks (FP-201)  
**Status:** Fixed and verified

## Evidence

Incident log FP-201: the bank sent the same callback twice and two identical notes were stored. Migration `0051` left `callback_id` non-unique and comments pointed at a missing `processed_events` table. `applyAcquirerCallback` was a plain INSERT.

## Fix

Migration `0078` deduplicates existing rows and adds `uq_acquirer_callback_notes_callback_id`. The insert uses `ON CONFLICT (callback_id) DO NOTHING`.

## Regression coverage

`callbacks.replay.new.test.ts`: sequential and concurrent redelivery of one `callback_id` leave a single note. **2 pass / 0 fail** against local Compose Postgres after `0078`.
