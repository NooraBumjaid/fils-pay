# BUG-048: Payment-link crash recovery could charge twice

**Severity:** High  
**Component:** Payment links  
**Status:** Fixed and verified

## Evidence

A worker that captured the card but crashed before `status = 'paid'` left
the link `reserved`. After the reservation timeout, a retry with a new
client idempotency key authorized a second transaction.

## Fix

Migration `0077_payment_link_payment_attempts.sql` stores:

- `payment_attempt_key` — stable authorize/capture idempotency scope
- `reservation_id` — lease for the current worker

Reclaim keeps the original attempt key (`COALESCE`) and mints a new lease.
Release and finalize are scoped to that lease so an in-flight worker cannot
be stolen. Public expiry still uses the server clock (FP-187).

## Regression coverage

`pay.recovery.integration.test.ts` simulates a crash on finalize, waits for
the lease to expire, retries with a new client key, and asserts one
transaction and `status = 'paid'`. Existing payment-link route tests still
pass, including expired-link 410 and same-key timeout replay.
