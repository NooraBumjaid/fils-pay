# BUG-011 — Refunds could cross merchant boundaries

**Severity:** Critical — unauthorized financial operation  
**Area:** FP-300, API authorization

## Finding

Refund lookup selected a transaction by UUID alone. A merchant who learned another merchant's transaction UUID could trigger a refund, while the service posted it against the owning merchant.

## Fix

Scope transaction lookup by both transaction ID and authenticated merchant ID, and return `transaction_not_found` when the pair does not match.

## Verification

Added regression coverage for cross-merchant refund rejection. Static typecheck passes; the database-backed regression requires a migrated PostgreSQL database and was not executable in this environment.
