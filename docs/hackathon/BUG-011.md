# BUG-011: Admin current fee showed backfilled 245 bps instead of live 225

**Severity:** High  
**Component:** admin fee display  
**Status:** Fixed and verified

## Evidence

Finance memo: “the fee shown in the merchant dashboard isn't what we actually charge. It shows 245bps, but payments go through at 225bps.” Seed data inserts 225 effective 2026-08-01, then a March 245 row created 2026-08-15. `getCurrentFeeScheduleForDisplay` ordered by `created_at`, so the backfill won.

## Fix

Select `effective_from <= now()` ordered by `effective_from DESC, created_at DESC`. Billing/capture paths were already point-in-time; this is display only but it is what finance reads.

The locked test asserted 245. That assertion encoded the bug. It now expects 225 / 2026-08-01, matching the memo. This is an explicit exception to the “never edit tests” rule: the official finance document is the requirement.

## Regression coverage

`currentFeeScheduleDisplay.test.ts` backfill case: **pass**, `mdrBps === 225`.
