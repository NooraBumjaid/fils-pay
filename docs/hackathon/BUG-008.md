# BUG-008 — Built-in development encryption key has invalid length

**Severity:** High for local startup and development  
**Status:** Fixed in this branch

## Evidence

The development fallback decoded to 34 bytes, while
`parseWebhookSecretEncryptionKey` rejects every key not exactly 32 bytes.
With no explicit key (the documented development setup), `loadConfig`
therefore threw during API boot.

## Fix and coverage

Replaced the fallback with a valid 32-byte development-only key. The config
regression test now loads development config without an explicit key and
checks the decoded key length. Production still requires an explicit key.
