# BUG-014 — Successful refunds were omitted from settlement batches

**Severity:** Critical — payout and merchant balance incorrect  
**Area:** FP-300, settlement

## Finding

Settlement batch close selected capture events only. Successful refunds were not claimed by a batch, so frozen payout totals and settlement reporting omitted refund principal and fee reversals.

## Fix

CloseBatch now locks eligible successful refunds in the batch window, records refund and fee reversal totals, claims refund rows, and deducts refund principal net of reversed fees from the frozen payout. Refund deductions that exceed the current payout carry as a negative payable balance rather than generating a negative cash disbursement. Added schema fields through migration 0073.

## Verification

Added a PostgreSQL settlement regression test for a partial refund and its fee reversal. `go test ./internal/settlement` passes against the isolated migrated PostgreSQL database. The complete Go suite still has two existing `internal/ledger` refresh test failures because those fixtures insert closed batches/export lines without the ledger entries that the rebuild implementation treats as authoritative.
