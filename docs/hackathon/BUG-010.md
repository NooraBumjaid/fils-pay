# BUG-010 — Refund API was still a 501 stub

**Severity:** Critical — merchant refunds unavailable  
**Area:** FP-300, API

## Finding

`POST /v1/refunds` returned 501 without validating the request, checking merchant authorization, calling the acquirer, or writing refund state. FP-300's refund helpers existed, but no route connected them to merchants.

## Fix

Wired the route to the refund service, require a valid transaction UUID and positive integer fils amount, require `Idempotency-Key`, and use the authenticated merchant writer actor. The web transaction detail page now exposes full and partial refunds with a stable idempotency key per submission.

## Verification

TypeScript workspace typecheck passes. Refund route database integration tests are present but could not run because this workspace has no configured `DATABASE_URL` or migrated PostgreSQL instance. The full `npm test` run likewise stops on those DB prerequisites.
