# BUG-010: Adjustment CSV amounts were posted as cents, not BHD

**Severity:** Critical  
**Component:** admin adjustment import  
**Status:** Fixed; legacy assertions conflict with the finance contract

## Evidence

The admin guide and finance engineering notes say adjustment CSV `amount`
values are BHD exactly as shown in the finance sheet. The old parser passed
the value through a two-decimal minor-unit parser, so `4.75` was posted as
475 fils (0.475 BHD) instead of 4,750 fils (4.750 BHD), a tenfold
under-adjustment. The import's ledger, payable cache, history, and audit
metadata all used the incorrectly parsed amount.

## Fix

Adjustment parsing now uses the canonical `parseBhdToFils` parser. Two-decimal
and three-decimal BHD inputs map to 4,750 and 4,755 fils respectively; negative
adjustments retain their sign.

## Regression coverage and test conflict

New parser tests and `adjustmentImport.fils.integration.test.ts` verify the
integer written to import history, ledger legs, and the merchant balance cache.
The legacy `adjustmentImport.test.ts` assertions expect 475 fils for `4.75`,
which contradicts the documented finance input unit. Those assertions were
left untouched under the repository's regression-lock rule; that legacy test
file therefore remains incompatible with the corrected BHD contract.
