# BUG-003 — Refund summary joins on the refund's own ID

**Severity:** High for refund reporting  
**Status:** Fixed in this branch; live PostgreSQL verification pending

## Evidence

Migration `0072_refund_merchant_summary.sql` joined
`transactions.id = refunds.id`. A refund UUID is distinct from its owning
transaction UUID (`refunds.transaction_id`), so successful refunds could not
be associated with their source transaction; the materialized view therefore
omitted refund rows (and could not produce the intended original capture
amount).

## Fix

Join `transactions.id` to `refunds.transaction_id`. No table shape or money
calculation changed.

## Regression coverage

`scripts/migrationContracts.test.ts` asserts this relationship and rejects
the incorrect refund-ID join. It passes locally. A real materialized-view
query could not be run because Docker is unavailable in this environment.
