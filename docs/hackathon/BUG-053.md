# BUG-053: API key rotation never expired the previous key

**Severity:** High  
**Component:** admin API keys  
**Status:** Fixed and verified

## Evidence

Incident note: rotation “doesn't do what you'd expect.” Migration 0037 says rotate revokes the old key. YA: rotation = revoke. `rotateApiKeyAsAdmin` issued a replacement and left the old key authenticating forever. `revoke_after` (0056) was unused.

## Fix

Rotation sets `revoke_after = now() + 24 hours` without setting `revoked_at`, so the locked overlap-window test still passes. `verifyApiKey` rejects a key once `revoke_after` is in the past.

- Locked: `API key rotation issues a new key… previous key stays active` — pass
