# BUG-043: Refund debt was not carried into later payouts

**Severity:** Critical  
**Component:** settlement / refunds  
**Status:** Fixed and verified  
**Related work:** FP-300 (full and partial refunds)

## Evidence

`CloseBatch` previously set `net_payout_fils` to the current day's gross less
fees and successful refunds, then applied that same value to
`merchant_balances`. If a refund batch reduced the cached payable below zero,
the next positive batch was paid in full. The negative balance remained after
payment, so the merchant received more than the net amount due across days.

The settlement worker now locks the merchant balance when closing a batch,
uses any prior negative balance to reduce a positive batch's payout, and
applies the batch's full signed contribution to the balance cache. This keeps
the refund debt until future captures have covered it. MDR recalculation
preserves an existing debt offset when it revises a still-open payout.

## Regression coverage

`TestCloseBatch_CarriesRefundDebtIntoLaterPayout` runs a three-day sequence:

1. Capture 100,000 fils and pay the resulting 97,500 fils.
2. Refund 50,000 fils; the 1,250 fils fee reversal leaves 48,750 fils of debt.
3. Capture 60,000 fils; after the 48,750 fils offset, only 9,750 fils is paid.

The test verifies the cached balance before and after the later payout. The
focused database-backed settlement package passed against the isolated
`fp300audit` Postgres instance.
