# BUG-009 — Compose used a committed development database password

**Severity:** High for deployment security  
**Status:** Fixed in this branch

## Evidence

Compose configured PostgreSQL with the static password
`filspay_dev_password` and embedded that same credential in every service's
database URL. The same compose file is documented as the hosted demo stack,
so a known development credential could protect a deployed database.

## Fix and coverage

Compose now requires `POSTGRES_PASSWORD` from the operator environment and
uses it consistently for PostgreSQL and every service connection. The
operations guide requires a URL-safe password because the value is embedded
in connection URLs. Regression coverage rejects the old default.
