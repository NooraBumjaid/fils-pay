# BUG-058: Merchant support could POST /v1/refunds

**Severity:** High  
**Component:** refunds  
**Status:** Fixed and verified

## Evidence

RefundDrawer is wrapped in `RequireRole allow={["owner", "finance"]}`. RequireRole is documented as UI-only. The refund route authenticated any merchant actor.

A support dashboard user (or a crafted session) could refund through the API.

## Fix

`POST /v1/refunds` chains `requireMerchantRole("owner", "finance")`. API keys still skip the role check (owner-issued, by construction). Locked refund tests use API keys.

## Tests

`refunds.support.new.test.ts` — pass. Locked `initiateMerchantRefund.test.ts` still pass.
