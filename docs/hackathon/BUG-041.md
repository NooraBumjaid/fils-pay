# BUG-041 — Login OTP could target another merchant account

**Severity:** High — authentication account confusion
**Area:** Merchant login

## Finding

After verifying a password for the requested merchant account, login searched for the OTP recipient by email alone. The same email can belong to multiple merchants, so the challenge could be issued for a different account than the one whose password was checked.

## Fix

Issue the OTP challenge directly to the merchant user resolved by the `(merchantId, email)` credential lookup.

## Verification

Added a two-merchant same-email regression that verifies the login and `/v1/auth/me` session remain bound to the account whose password was used. `apps/api/src/app.test.ts` passes against isolated PostgreSQL.
