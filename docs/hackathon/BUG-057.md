# BUG-057: Support impersonation could capture, void, and refund

**Severity:** Critical  
**Component:** merchant auth / impersonation  
**Status:** Fixed and verified

## Evidence

HANDOVER: impersonation is read-only. ADMIN.md: only super_admin may write while viewing as a merchant. MK: “impersonation is read-only, enforced in requireMerchantAuth.” YA: “impersonation can’t reach write routes.”

`requireMerchantAuth` accepts the grant. Capture, void, and refund call `requireMerchantWriterActor` with no `requireMerchantRole`. The writer helper mapped every impersonation grant to `merchant_session`, so a support operator could move money.

Locked `admin.test.ts` only covers owner/finance-gated writes (payment links, webhooks).

## Fix

`requireMerchantWriterActor` throws `forbidden` for `admin_impersonation` unless the mapped merchant-plane role is `owner` (super_admin, FP-178 / ADMIN.md).

## Tests

`requireMerchantWriterActor.new.test.ts`, `impersonation.write.new.test.ts` — pass.
