# BUG-046: Platform volume tier counter overflow revoked the earned tier

**Severity:** High  
**Component:** settlement / pricing  
**Status:** Fixed and verified

## Evidence

`platform_stats.total_processed_fils` is an `INTEGER`, while settlement added
batch volume with `int32` arithmetic. After the counter passed the 2,000,000,000
fils tier threshold and then exceeded the signed 32-bit maximum, it wrapped
negative. Both API and settlement tier readers interpreted that negative
counter as below threshold and stopped applying the earned 15 bps discount.

## Fix

The existing integer column remains unchanged. Settlement now saturates the
counter at the tier threshold, where further volume cannot affect the single
tier decision. Negative values from a legacy overflow are treated as an
already-earned tier and migration `0076` normalizes any such persisted value.

## Regression coverage

- The Go accumulator test crosses the threshold and verifies later volume
  cannot wrap or change the saturated counter.
- Go and API tier tests treat a negative legacy overflow value as tier earned.
- Migration `0076_platform_volume_tier_overflow.sql` applied successfully to
  the isolated audit database.

The full database-backed settlement package passed, and all five API
volume-tier tests passed against the isolated `fp300audit` database.
