# BUG-042 — Concurrent payout scans could race while creating settlement notifications

**Severity:** High — duplicate payout events
**Area:** Settlement outbox

## Finding

Two notification workers could both observe no existing `settlement.paid` event and insert one for the same paid batch. A prior `NOT EXISTS` check alone did not serialize concurrent inserts.

## Fix

Added a partial unique index on paid-event aggregate IDs and use `ON CONFLICT ... DO NOTHING` so a competing scan remains an idempotent success.

## Verification

Added a database-backed regression that runs two scans concurrently and asserts exactly one event with neither scan erroring. `go test ./internal/settlement` passes against isolated PostgreSQL.
